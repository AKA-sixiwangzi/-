# 旭能学院：固定岗位、角色与个人加课 V1.2（修订）

日期：2026-11-16。基于现有 SSM、SQL Server 与 Vue 架构扩展。

## 岗位模型

岗位本身固定为专业岗、管理岗、综合岗三个选项，没有子岗位或具体岗位名称，不能新增、改名或重新分类。数据库保留 `PROFESSIONAL`、`MANAGEMENT`、`GENERAL` 内部代码与这三个名称一一对应，界面直接显示岗位名称。

“组织与人员”可编辑员工的部门、岗位、职级，岗位下拉框直接选择三者之一。组织字典仅维护部门和职级。岗位和角色独立：管理岗员工不会自动获得部门负责人权限，专业岗员工也不会自动成为内训师。

## 四类角色

| 界面角色 | 保留的权限代码 | 权限范围 |
| --- | --- | --- |
| 普通员工 | EMPLOYEE | 自己的学习任务、课程、考试、成果；所有员工均可创作课程 |
| 内训师 | INSTRUCTOR | 普通员工能力，以及自己负责的课程和学员情况 |
| 部门负责人 | MANAGER | 普通员工能力，以及明确授权部门的数据与加课申请 |
| 组织发展部 | ADMIN | 培训管理员，管理全公司培训、组织人员、需求审批与课程授权 |

同一账号可兼任多种角色。员工创作的课程审核发布后可成为内训师，普通员工身份一直保留。原管理员、讲师、部门主管账号继续使用，权限代码不变。

负责人必须由组织发展部授予角色并配置可管理部门。所属部门与授权部门是不同配置，不能仅凭负责人本人属于某部门就推定其管理范围。

## 成长路线分配

路线仍可配置所有部门或指定多个部门，并设置岗位、职级。路线的适用岗位可选择专业岗、管理岗、综合岗之一，或不限定。路线配置完成并发布后，分配员工时必须先选择范围内的部门和岗位，再手动勾选人员。切换部门或岗位会清空之前的勾选，避免将上一组员工意外提交。

后端独立核验整批员工的启用状态、所选部门和岗位、路线适用部门和岗位约束；任何一人不符合条件就整批拒绝，不写入部分任务。不同部门或岗位可分批分配同一路线。保存或发布路线不自动分配人员。

## 负责人申请与组织发展部审批

1. 部门负责人进入“加课需求”，选择已发布课程、授权部门、岗位和员工，填写原因。
2. 可以关联某条成长路线，仅可选择已参加该路线的人员；也可提交独立的个人加课需求。
3. 提交后状态为待审批，组织发展部收到通知；此时不会开通课程。
4. 组织发展部查看申请人、课程、员工和原因，填写意见后通过或驳回。
5. 通过前再次检查课程是否仍已发布、人员及申请人是否仍启用、负责人是否仍有角色和部门授权，以及路线参加关系。
6. 审批通过后，课程进入指定员工的“我的课程”，并向员工及申请人发送通知。驳回不产生课程授权。已处理需求不可重复审批。

申请人可查看自己的需求与结果，组织发展部可查看全部需求。审批记录保存处理人、时间和意见。通知、授权与状态变更处于同一事务中。

这里的加课是为指定员工补充个人学习任务，不修改共享路线阶段，因此不会把新课程加到同一路线的其他员工，也不会改动已有成绩或通关记录。

## 管理员直接授权

组织发展部可在“课程授权与需求”直接指定员工和已发布课程，填写授权原因后开通学习，不必先创建负责人申请。普通员工、内训师和部门负责人不能调用此授权接口。

重复开通同一门课程复用原学习任务，不重置进度、完成状态或成绩。直接授权逐人逐课保存审计记录；员工收到课程开通通知。

## 数据库升级与验证边界

已有培训库按版本依次执行 `02-add-path-departments.sql`、`03-position-types-learning-requests.sql`、`04-fixed-positions.sql`，然后更新 WAR。已执行的前置脚本无需重建。增量脚本可重复执行，不需要新建数据库、不清空学习记录。全新数据库使用最新版 `01-schema.sql`，自动初始化三个岗位。

04将旧岗位合并到三个固定岗位：旧名称已是标准名称时优先按名称识别，否则按旧内部分类合并；同类优先保留已有标准名称的编号，否则保留最小编号。员工和路线的岗位引用一并映射，旧名称、编号和映射写入 `position_migration_archive`，学习任务、进度、成绩、角色和审批记录保留。

离线演示不依赖数据库，兼容已有浏览器数据，增加部门负责人身份和本地申请审批流程。演示结果不作为正式培训记录。真实 SQL Server 迁移和 Tomcat 端到端联调需在部署环境完成。
