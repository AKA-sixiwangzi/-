# 旭能学院培训流程 V1.3

日期：2026-11-17。基于现有 SSM、SQL Server、Vue 架构扩展。

本版覆盖员工账号、多格式课程、计划提醒、简答阅卷、线下参训及教学计划跟进。岗位继续固定为专业岗、管理岗、综合岗，没有具体子岗位。四类角色继续使用 `EMPLOYEE`（普通员工）、`INSTRUCTOR`（内训师）、`MANAGER`（部门负责人）、`ADMIN`（组织发展部），一个员工账号可兼任多种角色。此前的部门范围、部门和岗位筛选、加课申请及指定员工课程授权继续保留。

## 一、员工资料与登录账号同步创建

组织发展部在“组织与人员”填写姓名、部门、岗位和职级，调用 `POST /api/admin/employees`。员工资料与登录账号在同一事务创建，不必另外填写账号密码。账号使用随机唯一的 `EMP` 前缀标识，临时密码为随机20位字符。

成功响应同时返回员工资料和本次账号回执。临时密码只在创建响应中给出；员工列表、个人资料和审计不返回原始密码，数据库仅存密码哈希。关闭回执前应将登录信息交给对应员工，系统不提供从员工列表再次查看原密码的功能。

新账号的 `must_change_password=true`。真实API登录后，只允许读取本人身份、修改密码和退出，其他受保护业务接口返回403及首次改密说明；Vue相应引导至设置页。修改时校验旧密码，新密码至少12字符、UTF-8不超过72字节，且不得与旧密码相同。修改完成清除首次改密标记并使已有令牌失效，员工用新密码重新登录。

旧账号不会仅因数据库升级而被要求修改密码。原手动创建用户接口保留兼容用途；新版“添加员工”流程使用自动账号接口。离线演示的身份切换和创建回执仅用于体验，真实凭据校验以SSM后端为准。

## 二、多格式课件及纯资料课程

课程可以包含视频，也可仅包含必读资料。资料分为下列类型：

| 资料类型 | 创建方式与学习方式 |
| --- | --- |
| 文字/TXT（`TEXT`） | 输入正文，或上传UTF-8 TXT附件；至少具备其中一项 |
| PDF（`PDF`） | 上传PDF并关联文件；允许浏览器支持的预览或下载 |
| PPT/PPTX（`PPT`） | 上传PPT或PPTX；下载后用Office或兼容软件打开，不做在线转换 |
| 网页（`LINK`） | 保存有有效主机名的HTTP/HTTPS地址，禁止地址携带账号密码；打开外部页面 |

上传资源使用 `POST /api/files`，资料登记使用 `POST /api/courses/{id}/materials`，其中 `assetId` 引用上传结果。文件类型、内容及课程作者权限在服务端校验；把文件改扩展名不等于有效的PPT/PPTX。

新建资料界面默认勾选“必读”。必读资料计入课程完成条件；选读资料不阻塞完成。无视频的课程必须至少有一份有效必读资料才可提交审核，有视频时仍要求有效视频章节；组织发展部独立审核后才可学习。

员工打开资料后主动点击“确认已阅读”，调用 `POST /api/materials/{id}/acknowledge`。重复确认复用原记录；仅已分配且已发布的课程可确认。确认是员工的阅读声明，不是页面自动证明读完文件，也不产生视频播放秒数。

`GET /api/courses/{id}/learning-status` 统一返回完成状态与百分比。分母为视频章节数加必读资料数；全部视频章节满足有效播放规则，且所有必读资料已确认，课程才完成。PDF翻页、打开链接或拖动视频进度条不能代替服务端完成校验。纯资料课程也可作为考试前置课程。

旧资料在升级后默认选读，不重写既有学习结果。课程问答和出题仍使用已录入的文字正文，不自动提取PDF/PPT/网页全文或转写视频。

## 三、培训计划、负责人和提醒

组织发展部建立培训计划，指定时间、固定参训人员、已发布课程及可选考试；计划课程应覆盖所选考试的前置课程。课程自身配置课件、题目和实践作业，考试通过课程前置关系及计划关联呈现在跟进看板中。草稿发布后才生成参训任务。

可以指定任一启用员工为计划负责人，不要求其先成为内训师或部门负责人；省略时由创建人负责。此关系只赋予该计划的跟进和提醒配置权限，不授予其他计划、全公司管理或无关课程权限。

默认配置为截止前72小时开始提醒，每24小时重复，开启负责人结果推送。提前小时数支持0至8760，重复间隔支持1至720小时。组织发展部及当前负责人可改提醒规则，转交负责人只允许组织发展部；已关闭计划不能修改规则。

真实后端运行时约每小时检查已发布计划。达到配置时点后，对未完成人员发送站内到期或逾期提醒，并向负责人发送待完成/待评阅情况；培训结果变化后可向负责人推送结果摘要。已提交待人工评阅的任务明确标记为待评阅，不能当作已通过。

通知保存去重记录：相同周期的同类提醒不重复发送，相同结果状态也不反复推送。管理页“执行提醒”使用同一套规则，可能因未到时间或已通知而不产生新消息。这是站内消息功能，没有接入邮件或即时通信推送。离线演示仅在页面操作时模拟，不具备关闭页面后仍执行的后台排程。

## 四、简答题逐题人工阅卷

简答题使用 `TEXT` 题型，参考答案随试卷快照固定。交卷后，客观题自动评分；只要包含简答题，考试进入 `PENDING_GRADE`，最终总分暂不公布。空白简答也进入人工阅卷，老师需明确评分为0分。

阅卷人可为组织发展部、考试负责人或试卷负责人，只能查看和处理授权范围内的试卷，不能批改本人的考试。逐题填写0至该题满分之间的整数，可附不超过1000字的评语。已评分题目不能重复提交或覆盖。

全部题目都有评分后，系统才汇总总分，依据考试通过线计算是否通过，状态改为 `GRADED` 并通知员工。部分简答尚未评分时，个人成果、计划看板和结果推送继续显示待评阅，不能提前领取依赖考试通过的路线结果。

作业评分与考试简答评分分别保留：作业使用0至100分及评价反馈；不能用作业得分代替试卷简答分数。

## 五、线下培训、出勤和个人学时

组织发展部或内训师可建立线下场次，填写培训名称、时间、地点、授课内训师和固定人员名单，可选关联计划与课程。单场结束晚于开始，且不超过24小时；地点最多200字符。关联课程须为已发布课程，关联计划须已发布；同时关联时课程和人员均应属于所选计划。

组织发展部可安排启用员工及启用的内训师。内训师仅能安排本人授课，关联本人课程，并选择自己课程的学员；其管理范围不自动扩大到其他内训师或其他员工。

场次开始前只能查看名单。开课后，授课内训师或组织发展部可登记出勤（`PRESENT`）、缺席（`ABSENT`）或请假（`EXCUSED`），可填写0至100的整数成绩与备注。未操作的员工继续为待签到（`REGISTERED`），不会自动认定出勤。

登记或更正须填写原因，服务端保存前后状态、成绩变化、记录人和时间及备注审计，并通知员工。普通员工仅看本人场次和本人出勤记录，不能自行改签到、成绩或他人资料。

只有状态为出勤且场次已经结束，才按整场培训时长计入线下学时。缺席、请假、待签到、尚未结束均不计学时。线下学时在个人培训成果单独展示，不添加到视频有效播放时长，不代替关联视频课程的观看条件。

## 六、讲师与负责人计划跟进看板

`GET /api/teaching/plans` 返回操作者可跟进的计划。组织发展部可查全部；指定负责人可查所负责的整项计划；内训师可查包含本人课程的已发布计划，详情仅展示本人课程及对应任务。普通参训员工继续通过“培训计划”查看自己的任务。

看板按计划及员工筛选，展示课程、资料、关联考试、实践作业、完成状态、考试成绩/待阅卷、作业成绩/待评价及关联线下场次。计划级考试另有汇总，避免没有课程前置关系的考试被遗漏。看板不会把不同老师课程的学员成绩混入当前老师的数据范围。

普通员工被指定为负责人时，可从“培训计划”列表的“计划跟进”和“提醒规则”进入；不需要授予组织发展部角色。查看计划数据不等于拥有所有课程的编辑、阅卷或线下出勤登记权限，相关操作继续独立校验。
